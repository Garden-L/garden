# 속도 신호 이슈와 결정

이 예제의 권위 있는 이슈 기록이다. SRS, STS, 작업 패킷, 추적성 표는 결정 이유를 복제하지 않고 이 파일에 연결한다.

## ISSUE-001 — 전원 종료와 시간 초과

**상태:** 로컬 모델에서 `Verified`. **관찰한 공백:** `SRC-1`~`SRC-4`에는 전원을 끌 때 invalid 플래그와 대기 중인 시간 초과가 유지되는지 정의되어 있지 않다. **문제인 이유:** 가능한 두 동작은 SRS 수용 조건, 시험 판정 기준, 코드 상태를 다르게 만든다. 조용히 선택하면 틀린 이유로 시험이 통과할 수 있다.

**선택지:** A: 전원 종료 때 플래그와 시간 초과를 지우고 다시 켠 뒤 감시를 시작한다. 로컬 리셋은 단순하지만 앞선 고장 상태는 버린다. B: 전원 종료 후에도 유지한다. 고장 이력은 남지만 지속 저장과 시계 동작을 정해야 한다. **권고:** 지속 저장이 범위 밖인 이 학습용 로컬 모델에는 A를 쓴다. 실제 차량에서는 해당 전원·진단 동작을 책임자가 결정해야 한다.

**예시 결정:** 예제 모듈 책임자가 2026-11-22에 로컬 모델에 한해 A를 선택했다. 이전 공백은 [원본 메모](../source.md)에 남긴다. **반영:** [REQ-005](SRS.md), [TC-005](../02-sts/STS.md), [WORK-001](../04-implementation/WORK-001.md), [구현](../../../../src/speed_signal.py). 이는 베이스라인 승인 전의 예시 결정이다. 승인된 SRS/STS를 바꾸는 경우에는 [기준선 변경관리](../../../../../../playbooks/change-control.md)를 따른다.

**검증:** [test_TC_005](../../../../tests/test_speed_signal.py)가 [로컬 실행](../05-verification/evidence/unittest-2026-11-22.txt)에서 통과했고 [검증 기록](../05-verification/verification.md)에서 평가했다. **남은 한계:** ECU·HIL·차량 전원 근거는 없다. `Verified` 상태는 선언한 로컬 모델 범위에만 적용한다.
