## 1. 목적과 범위

이 SRS는 0.1 km/h 단위 정수와 정수 ms를 사용하는 작은 로컬 Python 속도 감시기의 동작을 정의한다. [가상 원본 메모](../source.md)와 기록된 결정에서 요구사항이 어떻게 이어지는지 보여준다. ECU 인터페이스, 버스 인코딩, HIL, 차량 동작, 안전 적합성, 릴리스는 범위 밖이다.

## 2. 시스템 맥락

로컬 시험 호출자가 속도값과 시간 tick을 보내고 invalid 플래그를 관찰한다. 전원 모드 호출자가 감시기를 끄고 켠다. 하드웨어 신호나 외부 진단 서비스는 모델링하지 않는다.

## 3. 사용자와 시나리오

시험 호출자는 유효·무효 속도를 보내고, 유효 메시지 없이 시간을 진행하고, 유효 메시지 뒤 복구를 관찰하며, 고장 중 전원을 끈다. 이 시나리오는 `REQ-001`~`REQ-005`에 연결된다.

## 4. 요구사항

| ID | 분류 | 요구사항 | 출처 | 우선순위 | 수용 조건 |
| --- | --- | --- | --- | --- | --- |
| REQ-001 | 기능 | 전원이 켜졌을 때 감시기는 0~2500의 속도값을 양 끝을 포함하여 수용해야 한다. | SRC-1 | 필수 | 양 끝값에서 invalid 플래그가 해제 상태다. |
| REQ-002 | 기능 | 전원이 켜졌을 때 수신 속도가 0 미만이거나 2500을 초과하면 invalid 플래그를 설정해야 한다. | SRC-2 | 필수 | -1과 2501에서 각각 설정된다. |
| REQ-003 | 기능 / 시간 | 전원이 켜진 상태에서 유효 속도 메시지 뒤 100 ms를 초과하도록 새 유효 메시지가 없으면 invalid 플래그를 설정해야 한다. | SRC-3 | 필수 | 마지막 유효 메시지 뒤 100 ms에는 해제, 101 ms에는 설정된다. |
| REQ-004 | 기능 / 상태 | invalid 상태 뒤 유효 속도 메시지 세 개를 연속 수신한 후에만 플래그를 해제해야 한다. | SRC-4 | 필수 | 첫째·둘째 뒤에는 설정, 셋째 뒤에는 해제 상태다. |
| REQ-005 | 기능 / 전원 상태 | 전원을 끌 때 invalid 플래그와 대기 중인 시간 초과를 해제하고 다시 켤 때까지 감시를 중단해야 한다. | SRC-5를 해결한 [ISSUE-001 결정](issues.md#issue-001--전원-종료와-시간-초과) | 필수 | 꺼진 동안 시간 초과가 없고, 다시 켠 뒤 첫 유효 메시지가 새 시간 창을 시작한다. |

## 5. 인터페이스와 데이터

로컬 모델은 정수 `speed_deci_kmh`, 정수 `now_ms`, `power_off`, `power_on` 연산을 받고 Boolean invalid 플래그를 관찰값으로 제공한다. 이는 차량 네트워크가 아닌 예제 API다. `REQ-001`·`REQ-002`는 속도 범위, `REQ-003`은 시간, `REQ-005`는 전원 상태를 정의한다.

## 6. 제약과 가정

예제는 타임스탬프가 감소하지 않으며 로컬 호출자가 시간 tick을 호출한다고 가정한다. 실제 차량의 스케줄링 지터나 전원 주기 뒤 상태 지속성은 정의하지 않는다. 이 한계는 목표 환경 요구사항을 몰래 해석한 결과가 아니라 로컬 범위 밖이다.

## 7. 미결사항과 결정

[ISSUE-001](issues.md#issue-001--전원-종료와-시간-초과)에 누락된 전원 종료 동작, 대안, 가상 책임자의 선택, 영향받는 요구사항·시험, 로컬 검증을 기록했다. 선언된 로컬 모델 범위 안에 열린 이슈는 없다. 실제 대상 환경에는 별도 전원 상태 결정과 근거가 필요하다.

## 8. 참조와 용어

[원본 메모](../source.md)는 가상 입력이다. 실행 절차는 [STS](../02-sts/STS.md), 전체 연결은 [추적성 표](../traceability.md)에 있다. “invalid 플래그”는 로컬 모델의 Boolean 유효성 관찰값이다.
