## 1. 목적과 범위

[SRS 개정 1](../01-srs/SRS.md) 에 대해 로컬 Python 모델을 검증한다. ECU, HIL, 차량, 안전, 릴리스 검증은 범위 밖이다. 실행 결과는 [검증 기록](../05-verification/verification.md)에서 평가한다. 이 문서는 사례와 기대 동작을 정의한다.

## 3. 시험 환경과 데이터

시험 대상은 [speed_signal.py](../../../../src/speed_signal.py), 구동 코드는 [test_speed_signal.py](../../../../tests/test_speed_signal.py)이며 로컬 Python 3 `unittest`를 쓴다. 속도는 0.1 km/h 단위 정수, 시간은 정수 ms다. 각 시험은 전원이 켜진 새 감시기에서 시작한다. 실제 ECU나 버스 자극은 없다.

## 4. 시험 전략

포함 범위와 엄격한 시간 초과에는 경계값 분석, 유효하지 않은 속도에는 동등 분할, 복구·전원 모드에는 상태 전이 테스트를 쓴다. 예제 루트에서 `python3 -m unittest discover -s tests -v`로 독립 사례 다섯 개를 실행한다. 관찰값이 아래 기대 결과와 같을 때 통과한다. [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt)를 보관한다. 물리적 시간 정확성이나 대상 통합은 평가하지 않는다.

## 5. 시험 사례와 절차

### TC-001: 유효 속도 양 끝값

**요구사항:** `REQ-001`. **기법:** 경계값 분석. **사전 조건:** 전원이 켜지고 invalid가 해제된 새 감시기. **데이터:** 0, 2500.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 0 ms에 속도 0을 보내고 플래그를 본다. | 해제 상태다. |
| 2 | 1 ms에 속도 2500을 보내고 플래그를 본다. | 해제 상태다. |

**합격 기준:** 두 양 끝값 모두 해제 상태. **근거:** [test_TC_001](../../../../tests/test_speed_signal.py), [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt).

### TC-002: 범위 바로 밖의 속도

**요구사항:** `REQ-002`. **기법:** 동등 분할과 경계값 분석. **사전 조건:** 값마다 전원이 켜진 새 감시기. **데이터:** -1, 2501.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 0 ms에 -1을 보내고 플래그를 본다. | 설정된다. |
| 2 | 감시기를 새로 만들고 0 ms에 2501을 보낸 뒤 플래그를 본다. | 설정된다. |

**합격 기준:** 범위 밖 두 영역 모두 플래그를 설정. **근거:** [test_TC_002](../../../../tests/test_speed_signal.py), [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt).

### TC-003: 엄격한 시간 초과 경계

**요구사항:** `REQ-003`. **기법:** 경계값 분석. **사전 조건:** 전원이 켜진 새 감시기. **데이터:** 유효 속도 100, 100·101 ms tick.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 0 ms에 속도 100을 받는다. | 플래그 해제. |
| 2 | 100 ms에 tick하고 플래그를 본다. | 계속 해제. |
| 3 | 101 ms에 tick하고 플래그를 본다. | 설정된다. |

**합격 기준:** 100 ms를 넘은 뒤에만 전이. **근거:** [test_TC_003](../../../../tests/test_speed_signal.py), [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt).

### TC-004: 유효 메시지 세 개 뒤 복구

**요구사항:** `REQ-004`. **기법:** 상태 전이 테스트. **사전 조건:** -1을 보내 invalid 설정. **데이터:** 1·2·3 ms의 유효 속도 100.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 첫 유효 메시지를 보내고 플래그를 본다. | 설정 유지. |
| 2 | 두 번째 연속 메시지를 보내고 플래그를 본다. | 설정 유지. |
| 3 | 세 번째 연속 메시지를 보내고 플래그를 본다. | 해제된다. |

**합격 기준:** 세 번째 뒤에만 해제. **근거:** [test_TC_004](../../../../tests/test_speed_signal.py), [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt).

### TC-005: 시간 초과 중 전원 종료

**요구사항:** `REQ-005`, [ISSUE-001](../01-srs/issues.md#issue-001--전원-종료와-시간-초과) 결정. **기법:** 전원 모드와 시간 경계를 가로지르는 상태 전이 테스트. **사전 조건:** 전원이 켜진 새 감시기. **데이터:** 속도 100, 0·101·500·501·601 ms.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 0 ms에 속도 100을 받고 101 ms에 tick한다. | 시간 초과로 플래그 설정. |
| 2 | 전원을 끄고 플래그를 본다. | 해제된다. |
| 3 | 꺼진 상태에서 500 ms에 tick하고 플래그를 본다. | 계속 해제. |
| 4 | 다시 켜고 501 ms에 속도 100을 받은 뒤 601 ms에 tick한다. | 새 100 ms 경계에서 해제 상태. |

**합격 기준:** 네 관찰이 모두 `REQ-005`와 일치. **근거:** [test_TC_005](../../../../tests/test_speed_signal.py), [실행 로그](../05-verification/evidence/unittest-2026-11-22.txt).
