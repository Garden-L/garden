# 요구사항 명세서 작성

이 명세서는 독자가 시스템의 범위와 요구 동작을 이해하고, 각 요구사항의 충족 여부를 판단할 근거를 찾을 수 있도록 구성합니다. 실제 충족과 문서 승인 여부는 해당 근거를 검토하는 사람이 판단합니다.

## 원본 확인

원본 자료와 적용 버전, 작성 목적, 시스템 경계를 확인하세요. 원본에서 의무, 설명, 제약, 아직 결정되지 않은 내용을 구분하세요. 출처끼리 충돌하면 어느 쪽이 옳은지 추정하지 말고 충돌한 부분과 영향을 받는 요구사항을 식별하세요.

## 강제 사항
아래 원칙들은 반드시 지켜져야 합니다.
* 구현된 코드가 있더라도 구현 코드를 요구사항의 근거로 삼거나, 코드에 맞춰 요구사항을 만들어내지 마세요. -> 요구된 문서에 집중합니다.
* 사양에 서로 일치되지 않은 내용이 있거나 요구사항에 판단에 필요한 조건이 빠져 있으면 반드시 식별하세요. 여기서 부족한 부분은 행위자, 입력, 출력, 조건, 시점, 예외, 권한 또는 완료 판단 기준 중 하나 이상이 없어 서로 다른 해석이 가능한 경우를 뜻합니다.
* 미결사항마다 가능한 해결 대안을 구체적으로 제시하세요. 대안은 요구사항의 동작이나 범위가 달라지는 선택지여야 하며, 해결할 수 있는 모든 대안을 제시하세요. 현실적인 대안이 하나뿐이면 그 이유와 다른 대안을 배제한 근거를 기록하세요.
* 각 대안에 대해 장점, 단점, 영향받는 요구사항 ID, 수용 조건·시험, 구현 또는 운영 범위에 미치는 영향을 비교하세요. 비교 없이 권장안만 제시하지 마세요.
* 권장안은 결정된 사항이 아닙니다. 권장안, 확정된 결정, 결정권자 또는 결정 기한이 필요한 미결사항을 서로 구분하고, 권한이 없는 결정을 임의로 확정하지 마세요.
* 미결사항과 해결 대안은 독자가 이해할 수 있는 수준으로 쉽게 설명하세요. 낯선 용어는 뜻을 밝혀 쓰고, 표현을 쉽게 바꾸더라도 시간·조건·예외처럼 판단에 필요한 의미는 유지하세요. 대안의 순서를 정할 때는 비용, 위험, 요구사항 충족도 등 판단 근거를 함께 적으세요.

## SRS 작성

독자가 범위와 맥락을 이해한 다음 요구사항을 해석할 수 있도록 문서를 구성하세요. 문서 형태가 필요하면 [SRS 형식](references/srs-format.md)을 참고하고, 완성된 표현의 한 가지 예가 필요하면 [SRS 예시 디렉토리](examples/)를 참고하세요. 형식을 고정 레이아웃으로 취급하지 마세요.

- 원본의 각 의무가 SRS의 어느 요구사항 또는 미결사항으로 이어지는지 확인하세요. 누락된 의무를 조용히 버리거나 같은 의무를 서로 다른 뜻으로 중복 기술하지 마세요.
- 범위와 시스템 맥락을 설명하고, 요구사항을 이해하는 데 필요한 행위자, 인터페이스, 데이터, 제약, 가정을 연결하세요. 출처가 뒷받침하지 않는 요소를 문서의 빈칸을 채우기 위해 만들지 마세요.
- 각 요구사항에 출처와 관찰 가능한 판단 조건을 연결하세요. 설명, 요구사항 ID, 수용 조건이 서로 다른 동작을 가리키면 의미를 맞추세요.
- 출처가 충돌하거나 동작을 정하지 않은 경우에는 확정된 요구사항과 구분해 영향을 받는 부분에 미결사항을 연결하세요. 해결할 권한이 없는 결정을 임의로 확정하지 마세요.
- 미결사항을 작성할 때는 다음 정보를 포함하세요: 미결사항, 발생 이유, 가능한 대안, 대안별 장점·단점, 요구사항·시험·구현 또는 운영 영향, 권장안, 결정 상태와 다음 조치.
- 문장, 표, 그림은 관계나 흐름을 독자가 더 분명히 이해할 때 사용하세요. 그림을 추가하더라도 요구사항과 출처의 연결이 사라지지 않게 하세요.

## 문서 점검

원본의 각 의무를 SRS에서 찾을 수 있는지, 각 요구사항의 출처와 판단 조건을 찾을 수 있는지 확인하세요. 범위·인터페이스·제약·가정 사이의 모순과 연결되지 않은 항목을 살피세요. 원본이 바뀌면 영향받는 설명과 요구사항, 판단 조건을 다시 확인하세요. 모든 미결사항에 대해 대안 비교가 있는지도 확인하세요. 각 대안의 장점·단점과 요구사항·시험·구현 또는 운영 영향이 빠졌다면 결과를 완료된 명세로 제시하지 말고 해당 누락을 명시하세요. 구조가 맞는지만 보고 내용의 충족이나 문서 승인을 주장하지 마세요.

## 결과 제시

완성된 SRS를 독자가 검토할 수 있게 제시하세요. 어떤 원본이 어떤 범위에 반영됐는지, 아직 반영되지 않은 의무와 해결되지 않은 충돌·결정이 무엇인지 구분하세요. 필요한 설명이나 그림은 해당 요구사항과 함께 읽을 수 있게 연결하세요.
