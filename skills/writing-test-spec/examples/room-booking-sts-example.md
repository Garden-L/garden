# 소프트웨어 시험 명세서: 회의실 예약

| 항목 | 내용 |
| --- | --- |
| 문서 ID | STS-ROOM-RETEST-001 |
| 버전 | 0.3, 요구사항 확인 범위 재점검 초안 |
| 입력 요구사항 | [SRS-ROOM-RETEST-001 v0.2](SRS-retest.md) |
| 상태 | 미실행. SRS의 미결사항 때문에 일부 실행 조건이 정해지지 않았다. |

## 목적과 범위

회의실 조회, 중복 예약 방지, 예약 성공, 예약번호 제공을 시험한다. 취소와 확인 알림은 SRS에서 요구 동작이 확정되지 않아 아직 합격 기준을 만들지 않는다. 이 문서는 시험 사례를 설계한 것이며 실제 시험 결과가 아니다.

## 요구사항과 시험 사례 연결

| 요구사항 | 합격 조건 | 시험 사례 | 확인하는 조건 |
| --- | --- | --- | --- |
| REQ-001 | 지정한 날짜와 시간에 예약할 수 있는 회의실이 조회 결과에 나타난다. | TC-001 | 예약 가능한 방이 있는 경우 |
| REQ-001 | 예약 가능한 방이 없으면 어떤 방도 예약 가능으로 나타나지 않는다. | TC-002 | 예약 가능한 방이 없는 경우 |
| REQ-002 | 같은 회의실에 시간이 겹치는 두 번째 예약이 만들어지지 않는다. | TC-003 | 시간이 완전히 겹치는 경우 |
| REQ-002 | 같은 회의실에 시간이 겹치는 두 번째 예약이 만들어지지 않는다. | TC-004 | 시간이 일부만 겹치는 경우 |
| REQ-003 | 예약 가능한 회의실을 요청하면 선택한 회의실과 시간에 예약이 만들어진다. | TC-005 | 예약 가능한 방을 선택한 경우 |
| REQ-004 | 예약 성공 결과에서 예약번호를 확인할 수 있다. | TC-005 | 예약에 성공한 경우 |

사례별 합격 조건은 [SRS의 요구사항 표](SRS-retest.md)에 적힌 동작에서 도출했다. REQ-001은 예약 가능한 방이 있는 때와 없는 때를, REQ-002는 시간이 완전히 겹치는 때와 일부 겹치는 때를 구분해 확인한다. REQ-003과 REQ-004는 같은 예약 동작에서 확인할 수 있으므로 TC-005를 공유한다. 다른 요구사항의 의무를 새로 만들지는 않았다.

## 시험 조건

시험을 시작할 때 사용할 회의실 `가`와 `나` 및 기존 예약을 통제할 수 있어야 한다. 날짜 `D`와 시각 `10:00` 같은 값은 시험 데이터다. 어느 지역의 시각인지와 회의실 목록을 어디에서 가져오는지는 SRS의 ISSUE-003/004 결정에 맞춰 고정해야 한다. 예약이 실제로 만들어졌는지 확인할 관찰 수단도 시험 환경에서 마련해야 한다. 화면, API 또는 저장 방식은 이 STS가 정하지 않는다.

## 시험 사례

### TC-001: 예약 가능한 회의실 조회 — REQ-001 기본

- **준비:** 날짜 `D`의 `10:00~11:00`에 `가`는 비어 있고 `나`에는 예약이 있다.
- **수행:** 직원이 날짜 `D`, `10:00~11:00`로 회의실을 조회한다.
- **기대 결과와 합격 조건:** `가`가 예약 가능한 회의실로 나타나고 `나`는 예약 가능한 방으로 나타나지 않는다.
- **실행 전 확인:** ISSUE-003/004의 시각 기준과 회의실 목록이 정해져야 한다.

### TC-002: 예약 가능한 회의실이 없음 — REQ-001 추가

- **준비:** 날짜 `D`의 `10:00~11:00`에 목록의 모든 회의실이 예약돼 있다.
- **수행:** 직원이 날짜 `D`, `10:00~11:00`로 회의실을 조회한다.
- **기대 결과와 합격 조건:** 예약 가능한 회의실로 표시되는 방이 없다. 별도 안내 문구나 화면 모양은 요구하지 않는다.
- **실행 전 확인:** ISSUE-003/004의 시각 기준과 전체 회의실 목록이 정해져야 한다.

### TC-003: 완전히 겹치는 예약 거부 — REQ-002 기본

- **준비:** 회의실 `가`에 날짜 `D`, `10:00~11:00` 예약이 하나 있다.
- **수행:** 같은 회의실과 같은 시간으로 두 번째 예약을 요청한다.
- **기대 결과와 합격 조건:** 두 번째 예약은 만들어지지 않는다. 거부 메시지의 문구는 규정하지 않는다.
- **실행 전 확인:** 시각 기준과 예약 상태를 확인할 수단이 필요하다.

### TC-004: 일부 시간이 겹치는 예약 거부 — REQ-002 추가

- **준비:** 회의실 `가`에 날짜 `D`, `10:00~11:00` 예약이 하나 있다.
- **수행:** 같은 회의실에 `10:30~11:30` 예약을 요청한다.
- **기대 결과와 합격 조건:** `10:30~11:00`이 겹치므로 두 번째 예약은 만들어지지 않는다.
- **실행 전 확인:** 시각 기준과 예약 상태를 확인할 수단이 필요하다.

### TC-005: 빈 회의실 예약과 예약번호 제공 — REQ-003, REQ-004

- **준비:** 회의실 `가`에는 날짜 `D`, `09:00~10:00` 예약이 있고 `11:00~12:00`는 비어 있다.
- **수행:** 직원이 회의실 `가`를 날짜 `D`, `11:00~12:00`에 예약한다.
- **REQ-003 합격 조건:** 기존 예약과 겹치지 않는 `11:00~12:00` 예약이 만들어진다.
- **REQ-004 합격 조건:** 예약 성공 결과에 예약번호가 있다. 번호의 형식이나 전역 고유성은 원본이 정하지 않았으므로 판정하지 않는다.
- **실행 전 확인:** ISSUE-003/004의 결정과 예약 상태를 확인할 수단이 필요하다.

## 시험 공백

| 공백 | 관련 요구·사례 | 아직 정해지지 않은 것 | 다음 결정 |
| --- | --- | --- | --- |
| GAP-001 | SRS ISSUE-001 | 취소 허용 기한이 서로 충돌한다. | 취소 정책이 정해지면 경계 시각을 포함한 사례를 만든다. |
| GAP-002 | SRS ISSUE-002 | 알림 방법과 5초의 종료 시점이 없다. | 결정 후 성공·지연·실패 사례를 만든다. |
| GAP-003 | SRS ISSUE-003, TC-001~TC-005 | 날짜와 시각의 지역 기준이 없다. | 기준이 정해지면 시험 데이터와 경계 사례를 확정한다. |
| GAP-004 | SRS ISSUE-004, TC-001/002/005 | 회의실 목록의 관리 기준이 없다. | 목록을 준비·확인하는 방법을 정한다. |
| GAP-005 | REQ-002 | 한 예약이 끝나는 시각에 다음 예약이 시작하면 `겹침`으로 볼지 정해지지 않았다. | 구간 경계를 정한 뒤 경계값 사례를 추가한다. |
| GAP-006 | REQ-001/003 | 종료 시각이 시작 시각과 같거나 더 이른 입력의 결과가 없다. | 유효하지 않은 시간 입력의 동작을 정한 뒤 예외 사례를 추가한다. |

이 STS의 TC-001~TC-005는 모두 **설계만 완료**했다. 실행, 통과 또는 실제 환경에서의 충족은 주장하지 않는다.
