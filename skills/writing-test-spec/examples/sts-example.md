## 1. 목적과 범위

제공된 메모 생성, 편집, 삭제, 목록 정렬 요구사항을 검증한다. 계정과 동기화는 범위 밖이다.

## 2. 시험 근거와 추적성

| 입력 요구사항 | 요구 동작과 확인할 결과 |
| --- | --- |
| REQ-001 | 사용자가 제공한 제목과 본문으로 메모를 만든다. 저장 후 목록에 제목이 나타나고 다시 열면 본문이 보인다. |
| REQ-002 | 기존 메모의 제목과 본문을 수정한다. 저장 후 다시 열면 수정한 값이 보인다. |
| REQ-003 | 기존 메모를 삭제한다. 삭제 후 목록에서 찾거나 다시 열 수 없다. |
| REQ-004 | 최근 수정한 메모가 목록에서 맨 위에 보인다. |

| 요구사항 ID | 시험 사례 ID | 검증 범위 / 공백 |
| --- | --- | --- |
| REQ-001 | TC-001 | 메모 생성·재조회. 빈 제목 동작은 ISSUE-001 |
| REQ-002 | TC-002 | 편집·재조회 |
| REQ-003 | TC-003 | 메모 삭제 |
| REQ-004 | TC-002 | 수정 뒤 순서 변화 |

## 3. 시험 환경과 데이터

초기화된 로컬 앱을 사용한다. `TC-002`에서는 `가`, `나` 메모를 차례로 만들어 `가`가 먼저 작성된 상태를 준비한다. 이 예제는 시험을 명세할 뿐 앱이나 실제 실행 결과를 제공하지 않는다.

## 4. 시험 전략

생성·편집·삭제의 결과를 각각 확인한다. 편집과 최근 수정 순서는 같은 편집 동작 뒤에 별도로 관찰할 수 있어 `TC-002`에 함께 둔다. 관련 화면을 다시 열어 저장 상태를 확인한다. 요구사항이 빈 제목의 동작을 정의하지 않으므로 임의의 합격 기준을 만들지 않는다.

## 5. 시험 사례와 절차

### TC-001: 메모 생성

**요구사항:** `REQ-001`. **사전 조건:** 초기화된 앱. **데이터:** 제목 `첫 메모`, 본문 `기억할 내용`.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 메모를 만들고 저장한다. | 메모가 저장된다. |
| 2 | 목록을 열고 해당 메모를 연다. | 목록에 `첫 메모`가 있고 본문은 `기억할 내용`이다. |

**합격 기준:** 제목과 본문이 유지된다. **근거 계획:** 목록과 다시 연 메모의 관찰.

### TC-002: 메모 편집과 최근 수정 순서

**요구사항:** `REQ-002`, `REQ-004`. **사전 조건:** `가`를 만든 다음 `나`를 만들어 `나`가 목록에서 먼저 보이는 상태. **데이터:** `가`의 새 제목 `수정된 가`, 새 본문 `변경된 내용`.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | `가`의 제목과 본문을 바꾸고 저장한다. | 수정값이 저장된다. |
| 2 | 목록을 확인한 뒤 수정한 메모를 다시 연다. | `수정된 가`가 목록 맨 위에 있고, 다시 열면 본문에 `변경된 내용`이 보인다. |

**REQ-002 합격 기준:** 다시 연 메모의 제목과 본문이 수정한 값이다. **REQ-004 합격 기준:** 수정한 메모가 목록 맨 위에 있다. **근거 계획:** 목록 순서와 다시 연 메모의 관찰.

### TC-003: 메모 삭제

**요구사항:** `REQ-003`. **사전 조건:** 기존 메모.

| 단계 | 수행 내용 | 기대 결과 |
| --- | --- | --- |
| 1 | 메모를 삭제한다. | 삭제 동작이 완료된다. |
| 2 | 목록으로 돌아가 제목을 찾는다. | 메모가 없고 목록에서 다시 열 수 없다. |

**합격 기준:** 삭제한 메모를 목록에서 사용할 수 없다. **근거 계획:** 목록 관찰.

## 6. 시험 공백

**ISSUE-001:** 요구사항은 빈 제목을 허용할지 정하지 않았다. 따라서 빈 제목을 입력했을 때의 기대 결과를 아직 정할 수 없다. 요구사항 책임자가 동작을 정하면 관련 시험 사례를 추가한다. 그 전에는 합격 기준을 만들지 않는다.
