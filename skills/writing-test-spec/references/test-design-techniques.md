# 요구사항에 맞는 시험 설계 기법

이 자료는 시험 사례를 고를 때 참고하는 선택지다. 목표는 기법을 적용한 개수가 아니라 요구사항의 합격 조건을 충분히 확인하는 것이다. 입력, 조건, 상태와 시간의 특성을 살필 때 도움이 되는 기법만 사용한다.

| 요구사항의 특성 | 고려할 기법 | 시험 사례로 만드는 방법 |
| --- | --- | --- |
| 여러 입력이 같은 결과를 낸다 | 동등 분할 | 결과가 같은 유효·무효 입력을 묶고 각 묶음에서 대표 값을 고른다. |
| 최솟값·최댓값이나 시간 한계에서 결과가 달라진다 | 경계값 분석 | 의미 있는 최소 간격으로 경계 바로 안쪽, 경계, 바로 바깥쪽을 비교한다. 경계 포함 여부는 요구사항에서 확인한다. |
| 조건의 조합에 따라 결과가 달라진다 | 결정표 | 결과가 달라지는 조건의 조합을 구분하고 각 조합의 기대 결과를 적는다. |
| 상태나 모드에 따라 허용 동작이 달라진다 | 상태 전이 시험 | 시작 상태, 동작, 도착 상태와 관찰 결과를 연결한다. |
| 잘못된 입력이나 실패 후 동작이 정의돼 있다 | 예외·복구 사례 | 누락·잘못된 값, 시간 초과, 실패·복구 중 해당하는 조건을 재현한다. |

대표 값만으로 요구사항의 차이를 놓치지 않는지 살핀다. 같은 준비와 동작으로 여러 요구사항을 확인할 수 있으면 사례를 합치되 각 기대 결과를 별도로 관찰한다. 추가 사례의 기대 결과가 요구사항에서 도출되지 않으면 그 부분을 시험 공백으로 표시한다. 기법을 사용했다면 그 사례가 어떤 조건을 확인하는지 알 수 있게 한다.
