# 시험 명세서 작성

이 명세서는 독자가 무엇을 어떤 조건에서 시험하고 어떤 결과를 기대하는지 이해할 수 있게 한다. 작성한 사례는 시험 계획이며, 실제 통과 여부는 시험을 실행한 뒤에 판단한다.

## 원본 확인

주어진 요구사항과 시험할 범위를 확인하세요. 요구사항의 조건·경계·예외와 아직 정해지지 않은 동작을 구분하세요. 구현 코드에서 기대 동작을 추정해 요구사항의 빈 곳을 채우지 마세요.

## 강제 사항

- 요구사항마다 그 의무를 확인할 관찰 가능한 합격 조건과 기본 시험 사례를 만드세요. 각 사례를 근거 요구사항에 연결하세요.
- 요구사항이 충돌하거나 뜻이 부족해 합격 조건을 정할 수 없다면 그 부분과 필요한 결정을 시험 공백으로 표시하세요. 정해지지 않은 결과를 임의로 만들지 마세요.
- 작성한 시험 사례를 실제 실행 결과로 제시하지 마세요.

## STS 작성

독자가 시험 범위와 근거를 파악한 다음 각 사례를 재현할 수 있도록 문서를 구성하세요. 문서 형태가 필요하면 [STS 형식](references/sts-format.md)을 참고하고, 완성된 표현의 한 가지 예가 필요하면 [STS 예시](examples/sts-example.md)를 읽으세요. 형식을 고정 레이아웃으로 취급하지 마세요.

- 먼저 각 요구사항의 기본 합격 조건을 시험 사례로 표현하세요. 합격 조건을 정할 수 없는 부분은 이유를 밝혀 공백에 연결하세요.
- 그런 다음 관련된 경계값, 유효·무효 입력, 조건의 조합, 상태 변화, 시간 초과, 실패·복구를 검토하세요. 필요한 [시험 설계 기법](references/test-design-techniques.md)으로 추가 사례를 만들고 선택 이유를 적으세요. 요구사항에서 도출할 수 없는 새로운 동작을 합격 조건으로 만들지 마세요.
- 사례마다 필요한 준비, 입력 또는 동작, 순서, 관찰 지점과 기대 결과를 적으세요. 독자가 같은 조건에서 실행하고 합격·실패를 구분할 수 있어야 합니다.
- 시험 환경과 데이터가 결과에 영향을 주면 그 조건을 명시하세요. 필요한 환경을 아직 사용할 수 없다면 계획과 공백으로 표시하세요.

## 문서 점검

각 요구사항의 기본 합격 조건과 시험 사례가 빠짐없이 연결됐는지 확인하세요. 추가 사례는 해당 요구사항의 경계·예외를 실제로 구분하는지 살피세요. 사례의 입력·절차·기대 결과가 서로 맞고 요구사항으로 뒷받침되는지 확인하세요. 요구사항이 바뀌면 영향받는 사례와 시험 공백을 다시 확인하세요.

## 결과 제시

완성된 STS와 함께 시험으로 확인할 범위, 아직 시험할 수 없는 부분과 실행에 필요한 조건을 독자가 찾을 수 있게 제시하세요. 환경, ID와 승인 방식은 호출한 플레이북이 정합니다.
