# 시험 명세서 작성

이 명세서는 독자가 무엇을 어떤 조건에서 시험하고 어떤 결과를 기대하는지 이해할 수 있게 한다. 작성한 사례는 시험 계획이며, 실제 통과 여부는 시험을 실행한 뒤에 판단한다.

## 원본 확인

주어진 요구사항과 시험할 범위를 확인하세요. 요구사항의 조건·경계·예외와 아직 정해지지 않은 동작을 구분하세요. 구현 코드에서 기대 동작을 추정해 요구사항의 빈 곳을 채우지 마세요.

## 강제 사항

- 요구사항마다 그 의무를 확인할 관찰 가능한 합격 조건을 정하고, 이를 검증할 시험 사례를 필요한 만큼 만드세요. 한 요구사항을 여러 사례로 확인하거나 한 사례로 여러 요구사항을 확인할 수 있습니다. 어느 경우든 요구사항별 합격 여부를 구분할 수 있어야 합니다.
- 요구사항이 충돌하거나 뜻이 부족해 합격 조건을 정할 수 없다면 그 부분과 필요한 결정을 시험 공백으로 표시하세요. 정해지지 않은 결과를 임의로 만들지 마세요.
- 작성한 시험 사례를 실제 실행 결과로 제시하지 마세요.

## STS 작성

독자가 시험 범위와 근거를 파악한 다음 각 사례를 재현할 수 있도록 문서를 구성하세요. 문서 형태가 필요하면 [STS 형식](references/sts-format.md)을 참고하고, 완성된 표현의 한 가지 예가 필요하면 [STS 예시 디렉토리](examples/)를 참고하세요. 형식을 고정 레이아웃으로 취급하지 마세요.

- 먼저 각 요구사항의 합격 조건을 시험 사례로 표현하세요. 같은 준비와 동작으로 여러 요구사항을 확인할 수 있다면 사례를 합치고, 요구사항별 기대 결과는 분리해 적으세요. 조건이나 상태가 달라지면 필요한 사례로 나누세요. 합격 조건을 정할 수 없는 부분은 이유를 밝혀 공백에 연결하세요.
- 요구사항의 입력, 경계, 조건 조합, 상태 변화, 시간과 예외를 살펴 합격 조건을 충분히 확인할 만큼 사례를 만드세요. 방법을 고를 때 도움이 되면 [시험 설계 기법](references/test-design-techniques.md)을 참고하세요. 사례 수나 기법 사용 자체를 목표로 삼지 말고, 기대 결과가 정해지지 않은 조건은 시험 공백으로 표시하세요.
- 사례마다 필요한 준비, 입력 또는 동작, 순서, 관찰 지점과 기대 결과를 적으세요. 독자가 같은 조건에서 실행하고 합격·실패를 구분할 수 있어야 합니다.
- 시험 환경과 데이터가 결과에 영향을 주면 그 조건을 명시하세요. 필요한 환경을 아직 사용할 수 없다면 계획과 공백으로 표시하세요.

## 문서 점검

각 요구사항의 합격 조건이 필요한 사례들로 충분히 확인되는지 살피세요. 한 사례가 여러 요구사항을 다룬다면 각 합격 조건을 따로 판정할 수 있는지 확인하세요. 결과를 구별하는 데 필요한 조건이 사례나 공백에서 빠지지 않았는지 확인하세요. 사례의 입력·절차·기대 결과가 서로 맞고 요구사항으로 뒷받침되는지 살피세요. 요구사항이 바뀌면 연결된 모든 사례와 시험 공백을 다시 확인하세요.

## 결과 제시

완성된 STS와 함께 시험으로 확인할 범위, 아직 시험할 수 없는 부분과 실행에 필요한 조건을 독자가 찾을 수 있게 제시하세요.
