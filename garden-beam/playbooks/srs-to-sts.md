# SRS에서 STS 작성

자동차 SRS를 시험 가능한 STS로 만들 때 사용합니다.

1. SRS 리비전, 범위, 열린 결정을 확인합니다.
2. `spec-tests`를 적용해 각 사례를 추적 가능하게 만들고 기대 결과를 관찰 가능하게 정합니다. 범위·시간에는 경계값, 조건의 조합에는 결정표, 모드·복구에는 상태 전이처럼 요구사항에 맞는 기법을 고릅니다. [자동차 STS 맥락](../references/automotive-sts-context.md)을 참고해 관련 차량 상태, 전원 모드, 신호 범위·유효성, 타이밍, 고장, 복구, 인터페이스, 권한 조건을 선택합니다.
3. 각 테스트의 관찰 가능한 기대 결과는 SRS 또는 승인된 결정으로 뒷받침되어야 합니다. 동작이 정의되지 않았다면 합격 조건을 만들지 말고 `ISSUE`와 커버리지 공백을 연결합니다.
4. 알려진 환경, 자극, 관찰 지점, 근거를 실제 기준으로 기록합니다. 계획한 검사와 실행 결과를 구분하고, 이용할 수 없는 ECU/HIL/차량 환경은 공백으로 표시합니다.
5. 공용 `review`를 적용하고 [STS 검토 체크리스트](../references/sts-reviewer-checklist.md)로 SRS-STS 연결, 경계 사례, 절차 순서, 기대 결과, 결정에 따른 공백을 확인합니다.
6. 커버리지를 보고하기 전에 `verification`을 적용합니다. 실행하지 않은 테스트나 타깃 근거를 주장하지 않습니다.

산출물: 추적 가능한 테스트 케이스, 선정 근거가 있는 설계 기법, 실행 가능한 절차, 명시된 시험 공백을 포함한 STS. 프로젝트에서 달리 정하지 않으면 한국어를 씁니다. 공용 STS 형식은 필수가 아닌 참고용이며, [자동차 STS 예시](../references/automotive-sts-example.md)는 표현 예시입니다.
