# SRS에서 STS 작성

SRS를 시험 가능한 STS로 만들 때 사용합니다.

1. SRS 리비전, 범위, 열린 결정을 확인합니다.
2. `writing-test-spec`를 적용해 SRS의 각 시험 가능한 요구사항에 관찰 가능한 합격 조건을 정하고 사례나 공백에 연결합니다. 한 사례로 여러 요구사항을 확인할 수 있으면 합치되 합격 조건은 요구사항별로 구분합니다. [STS 고려사항](../references/sts-context.md)을 참고해 관련 입력, 상태, 시간, 실패·복구, 인터페이스와 권한 조건을 살피고 충분한 사례를 만듭니다.
3. 각 테스트의 관찰 가능한 기대 결과는 SRS 또는 승인된 결정으로 뒷받침되어야 합니다. 동작이 정의되지 않았다면 합격 조건을 만들지 말고 `ISSUE`와 커버리지 공백을 연결합니다.
4. 알려진 환경, 자극, 관찰 지점, 근거를 실제 기준으로 기록합니다. 계획한 검사와 실행 결과를 구분하고, 필요한 대상 환경을 사용할 수 없으면 공백으로 표시합니다.
5. 공용 `review`를 적용하고 [STS 검토 체크리스트](../references/sts-reviewer-checklist.md)로 SRS-STS 연결, 요구사항별 합격 조건과 사례의 충분성, 절차 순서, 기대 결과, 결정에 따른 공백을 확인합니다.
6. 커버리지를 보고하기 전에 `verification`을 적용합니다. 실행하지 않은 테스트나 타깃 근거를 주장하지 않습니다.

산출물: 요구사항별 합격 조건을 충분히 확인하는 시험 사례, 실행 가능한 절차, 명시된 시험 공백을 포함한 STS. 프로젝트에서 달리 정하지 않으면 한국어를 씁니다. 공용 STS 형식은 필수가 아닌 참고용이며, [STS 예시](../references/sts-example.md)는 특정 시스템을 사용한 표현 예시입니다.
