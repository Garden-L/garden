# 자동차 STS 고려사항

공통 `spec-tests`의 [형식](../../skills/spec-tests/formats/sts.md)은 구성 예시로만 사용한다. STS에는 필요에 따라 문장, 목록, 표, 다이어그램을 사용할 수 있다.

- SRS에 정의된 차량 상태, 점화·전원 모드, 신호 범위·유효성, 시간 초과, 고장, 복구, 인터페이스, 권한 규칙에서 시험 조건을 도출한다. 모든 범주가 항상 적용된다고 가정하지 않는다.
- 적절한 시험 설계 기법을 적용한다. 수치·시간 한계에는 경계값 분석, 모드·고장 복구에는 상태 전이 테스트가 예다. 관련 요구사항이나 시험 사례 근처에 선택 이유를 설명한다.
- 실행 가능한 각 `TC`에 근거 `REQ`, 차량 또는 시스템의 초기 상태, 자극·데이터, 관찰 가능한 응답, 합격 기준, 근거를 밝힌다. 순서가 중요하면 절차를 순서대로 적는다.
- 실제 환경과 관찰 지점을 알면 기술한다. 예를 들어 시뮬레이터, 벤치, ECU, HIL이 있다. 알 수 없으면 하드웨어나 도구를 지어내지 않고 가정 또는 공백으로 표시한다.
- 기대 동작이 뒷받침되는 엣지 케이스는 다른 `TC`로 만든다. 동작이 정의되지 않았으면 합격 결과를 부여하지 말고 `ISSUE`와 영향받는 검증 범위를 기록한다.
- SRS 버전과 `REQ` → `TC` 추적성을 보존한다. 실행 전 계획과 실행 결과를 구분한다.

[자동차 STS 예제](automotive-sts-example.md)는 한 가지 표현 방식이다.
