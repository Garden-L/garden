# STS 고려사항

공통 `writing-test-spec`의 [형식](../../skills/writing-test-spec/references/sts-format.md)은 구성 예시로만 사용한다. STS에는 필요에 따라 문장, 목록, 표, 다이어그램을 사용할 수 있다.

- SRS에 정의된 입력 범위·유효성, 상태, 시간 제한, 실패, 복구, 인터페이스, 권한 규칙에서 시험 조건을 도출한다. 모든 범주가 항상 적용된다고 가정하지 않는다.
- 요구사항별 합격 조건을 충분히 확인할 수 있는 사례를 고른다. 수치·시간 한계에서 결과가 달라지면 경계값 분석을, 모드·고장 복구에서 동작이 달라지면 상태 전이 시험을 참고할 수 있다. 기법 사용이나 사례 수 자체를 목표로 삼지 않는다.
- 실행 가능한 각 `TC`에 근거 `REQ`, 시스템의 초기 상태, 자극·데이터, 관찰 가능한 응답, 합격 기준, 근거를 밝힌다. 순서가 중요하면 절차를 순서대로 적는다.
- 실제 환경과 관찰 지점을 알면 기술한다. 알 수 없으면 환경이나 도구를 지어내지 않고 가정 또는 공백으로 표시한다.
- 기대 동작이 뒷받침되는 조건은 필요한 사례로 확인한다. 같은 준비와 동작에서 여러 `REQ`를 확인할 수 있으면 한 `TC`에 묶고 합격 조건을 각각 판정한다. 동작이 정의되지 않았으면 합격 결과를 부여하지 말고 `ISSUE`와 영향받는 검증 범위를 기록한다.
- SRS 버전과 `REQ` → `TC` 추적성을 보존한다. 실행 전 계획과 실행 결과를 구분한다.

[STS 예제](sts-example.md)는 한 가지 표현 방식이다.
