# 스킬 라이브러리 분류 구현 계획

> **작업 에이전트:** 이 계획은 `superpowers:executing-plans`로 작업별 실행한다.

**목표:** 자동차 흐름을 도메인 패키지로 유지하면서 스킬 라이브러리를 목적 중심 범주로 재구성한다.

**구조:** 공용 스킬만 중첩된 목적 범주로 옮긴다. 자동차 하위 스킬은 패키지에 두고 모든 목차와 이름·파일 중앙 등록부를 갱신한다. 플레이북에서는 경로를 직접 쓰지 않는다.

**기술:** Markdown과 파일 이동.

**설계 문서:** `docs/superpowers/specs/2026-11-22-skill-library-taxonomy-design.md`

## 공통 제약

- 스킬 이름과 핵심 지침을 보존한다.
- 기존 사용자 작업과 무관한 문서를 지우지 않는다.
- 자동차 표준과 수명주기 게이트는 자동차 패키지에 둔다.
- 플레이북은 이름으로 스킬을 가리키고 자동차 라우터가 경로를 찾는다.

## 검토 초점

- 이동한 스킬을 루트 README와 관련 도메인 라우터에서 찾을 수 있어야 한다.
- 등록부의 모든 경로가 이동 후에도 유효해야 한다.
- 자동차 플레이북에 공용 스킬의 오래된 경로가 남아서는 안 된다.
- 최상위 `skills/`가 모든 스킬의 실제 목적이 같다는 뜻으로 보이지 않아야 한다.

### 작업 1: 공용 스킬을 목적별 범주로 이동

**파일:** 승인된 설계 대응표에 따라 기존 스킬 디렉터리를 이동하고 내부 파일을 보존한다.

- [ ] 프레임: `architect`, `input-review`, `change-impact` 이동.
- [ ] 빌드: 소프트웨어의 `tdd`, 자동화의 `pattern-to-tool` 이동.
- [ ] 증명: `verification`, `verification-evidence`, `traceability` 이동.
- [ ] 전달: 학습 분야의 `programming-coursebook-authoring` 이동.
- [ ] 유지: `git-hygiene` 이동.

### 작업 2: 목차와 경로 갱신

**파일:** `README.md`, `garden-beam/README.md`, `garden-beam/skills/automotive-engineering/SKILL.md`, 관련 자동차 플레이북.

- [ ] README를 목적과 도메인 패키지 중심으로 다시 묶는다.
- [ ] 자동차 등록부 경로를 새 위치로 갱신한다.
- [ ] 자동차 플레이북은 이름만으로 스킬을 가리킨다.
- [ ] 이전의 평면 디렉터리 배치 참조를 제거한다.

### 작업 3: 결과 구조 확인

- [ ] 오래된 경로와 평면 배치 설명을 검색한다.
- [ ] 자동차 등록부의 모든 경로가 존재하는지 확인한다.
- [ ] 최종 diff에서 의도한 이동과 문서 변경만 있는지 확인한다.
