# Requirements to SRS

Use when supplied automotive requirements must become a Markdown SRS.

1. Read `../skills/software-requirements-specification/SKILL.md`.
2. Read `../../skills/shared/architect/SKILL.md` only if the request crosses a system or interface boundary.
3. Produce the SRS through the requirements skill's author/review/decision loop.
4. Preserve unresolved ambiguities as explicit open items; do not invent safety, standards, or architecture decisions.

Output: an SRS with requirement IDs, source sentences, issues/open items, decision records, and flows where needed.
