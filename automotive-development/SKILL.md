# Automotive Development

For use on another system, install the required sub-skills in pipeline order. The pipeline documents the dependency chain and distinguishes optional helper skills from environment prerequisites; do not silently substitute a missing skill or tool.

- For an end-to-end staged workflow from automotive requirements through SRS, STS, and implementation readiness, read and follow [Automotive Development Pipeline](skills/automotive-development-pipeline/SKILL.md).
- For a Markdown SRS based on sentence-level requirements, read and follow [Software Requirements Specification](skills/software-requirements-specification/SKILL.md).
- For creating an English Software Test Specification (STS) from an SRS, read and follow [Software Test Documentation](skills/software-test-documentation/SKILL.md).
- For an SRS and/or STS that must be checked before code or automated tests begin, read and follow [Implementation Readiness Review](skills/implementation-readiness-review/SKILL.md).
- For turning a readiness-reviewed SRS/STS into bounded implementation work packages and a bidirectional traceability matrix, read and follow [Implementation Backlog and Traceability](skills/implementation-backlog-traceability/SKILL.md).
- For implementing one approved work package within its packet and preparing a local commit, read and follow [Bounded Implementation Execution](skills/bounded-implementation-execution/SKILL.md).
- For reviewing an implementation against its requirements, tests, scope, and evidence, read and follow [Implementation Verification Review](skills/implementation-verification-review/SKILL.md).
- For a proposed change to an approved SRS, STS, interface, or acceptance criterion discovered during implementation, read and follow [Baseline Change Control](skills/baseline-change-control/SKILL.md).
- For other automotive workflows, use the applicable sub-skill under this directory when one exists.
