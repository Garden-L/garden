# Bounded Implementation

Use as the execution procedure when one approved `WORK-###` is ready to implement. Choose the feature, bug-fix, or refactoring playbook first to set the change-specific method.

1. Apply `implementation-backlog-traceability` to understand the work packet and traceability contract.
2. Apply `bounded-implementation-execution` for the implementation boundary and automotive work-packet rules.
3. Apply `engineering-design` to confirm packet inputs, boundaries, and readiness.
4. Apply `implementation` for the shared bounded execution and TDD method.
5. Preserve unrelated repository changes while inspecting or preparing the work item.
6. Run the selected behavior checks and update the work packet and traceability record with actual evidence.

Output: the bounded implementation, its checks, traceability updates, and a local commit when the leaf skill permits it.
