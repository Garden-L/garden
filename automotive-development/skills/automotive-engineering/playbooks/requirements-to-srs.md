# Requirements to SRS

Use when supplied automotive requirements must become a Markdown SRS.

1. Read `../../../../skills/input-review/SKILL.md`.
2. Read `../../software-requirements-specification/SKILL.md`.
3. Read `../../../../skills/architect/SKILL.md` only if the request crosses a system or interface boundary.
4. Produce the SRS through the requirements skill's author/review/decision loop.
5. Preserve unresolved ambiguities as explicit open items; do not invent safety, standards, or architecture decisions.

Output: an SRS with requirement IDs, source sentences, issues/open items, decision records, and flows where needed.
